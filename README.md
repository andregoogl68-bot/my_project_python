\## О проекте



Проект представляет собой телефонный справочник с возможностью:



\- добавления контактов;

\- редактирования контактов;

\- удаления контактов;

\- поиска по полям;

\- сохранения и загрузки данных из текстового файла.



В \*\*DZ\_1\*\* реализован монолитный вариант программы.

В \*\*DZ\_2\*\* код разделён на модули `model`, `view`, `controller`, добавлены классы, кастомные исключения и более строгая обработка ошибок.

Архитектура

model.py

Содержит бизнес-логику и работу с данными.



Основные классы и сущности:



Contact — контакт с атрибутами:

id;

first;

last;

phone;

comment.



PhoneBook — справочник контактов.



ContactReader — чтение контактов из файла.



ContactWriter — запись контактов в файл.



SEARCH\_FIELDS — соответствие пользовательских названий полей и атрибутов контакта.



model.py не печатает сообщения пользователю.



Методы add, update, delete, save возвращают результат: контакт или bool. 

Сообщения выводит контроллер через view.



view.py Централизует весь ввод и вывод:



печать таблицы контактов;



вывод меню;



запрос значений;



ask\_int с защитой от нечислового ввода;



confirm\_save;



show\_error.



При некорректном вводе ask\_int возбуждает InvalidContactIDError.



controller.py Содержит сценарии работы приложения:



edit\_contact;

search\_menu;

ask\_save\_on\_exit;

load\_from\_file;

main.



Главный цикл обёрнут в try/except PhoneBookError, поэтому ошибки показываются пользователю в формате:



\[Ошибка] ... Программа не завершается аварийно.



exceptions.py

Единая иерархия исключений с базовым классом PhoneBookError.



Исключения:



Все ошибки делятся на три группы:



Хранилище — StorageError:



ContactFileNotFoundError;



ContactFileFormatError;



ContactFileWriteError;



BackupError.



Валидация — ValidationError.



Операции с контактами:



ContactNotFoundError;



InvalidContactIDError.



У исключений есть удобные атрибуты, например:



field;



phone;



cid;



raw.



Контроллер может использовать их при обработке ошибок.

Домашнее задание DZ\_2

В DZ\_2 выполнены следующие требования.



1\. Код разбит на 3 модуля

view.py;



controller.py;



model.py.



model.py больше ничего не печатает:



методы add, update, delete, save возвращают результат — контакт или bool.

Сообщения пользователю выводит контроллер через view.



view.py централизует весь ввод/вывод:

печать таблицы, меню, запросы значений, ask\_int с защитой от нечислового ввода, confirm\_save.



controller.py содержит сценарии:

edit\_contact, search\_menu, ask\_save\_on\_exit, load\_from\_file, main и связывает модель и представление.





Точка входа — controller.py. Запуск:



Python controller.py

Модули должны лежать в одной папке или быть пакетом, чтобы импорты работали корректно.



2\. Созданы классы

Contact;



ContactReader;



ContactWriter;



PhoneBook.



Contact — полноценный класс с атрибутами:



id;



first;



last;



phone;



comment.



Реализованы:



\_\_eq\_\_ — для сравнения со снимком в dirty;



\_\_repr\_\_;



clone;



to\_dict;



from\_dict.



ContactReader и ContactWriter — отдельные классы со статическими методами, отвечают строго за I/O.



PhoneBook больше не работает с файлами напрямую. Он хранит list\[Contact] и использует ContactReader / ContactWriter.



Добавлено отображение SEARCH\_FIELDS, связывающее пользовательские имена полей и атрибуты контакта.



view.py и controller.py переведены на работу с атрибутами:



Python

c.id

c.first

c.last

c.phone

c.comment

вместо ключей словаря.



3\. Созданы кастомные исключения

exceptions.py содержит единую иерархию с базой PhoneBookError.



Все ошибки делятся на три группы:



хранилище — StorageError;



валидация — ValidationError;



операции с контактами — ContactNotFoundError, InvalidContactIDError.



У каждой ошибки есть удобные атрибуты:



field;



phone;



cid;



raw.



Контроллер при необходимости может их использовать.



Дополнительные изменения в DZ\_2

model.py:



ContactReader.load теперь строгий и возбуждает:



ContactFileNotFoundError;



ContactFileFormatError.



Добавлен ContactReader.load\_or\_empty — мягкий режим для старта справочника.



ContactWriter.save возбуждает:



BackupError;



ContactFileWriteError.



PhoneBook.get\_by\_id, update, delete возбуждают ContactNotFoundError.



PhoneBook.add проверяет:



пустой телефон;



пустые имя и фамилию;



дубликат телефона.



PhoneBook.update проверяет дубликат телефона.



view.py:



добавлена функция show\_error(error);



ask\_int теперь возбуждает InvalidContactIDError.



controller.py:



главный цикл обёрнут в try/except PhoneBookError;



любая ошибка показывается пользователю в формате \[Ошибка] ... без падения программы;



load\_from\_file использует строгий режим, чтобы сообщать о проблемах с явно указанным файлом.

Python controller.py
